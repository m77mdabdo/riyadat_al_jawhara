# Laravel 11 → 12 upgrade

Branch: `upgrade/laravel-12`, created from the final `feature/phase-8-plus` (`57ccbd5`). `feature/phase-8-plus` stays on Laravel 11 and is fully usable on its own.

Written 2026-09-30, **before** the upgrade (MASTER_TASK Phase 12, step 1). The results are in section 6.

## 1. Why: Laravel 11 is out of security support

Official support policy ([laravel.com/docs/12.x/releases#support-policy](https://laravel.com/docs/12.x/releases#support-policy)):

| Version | PHP | Released | Bug fixes until | Security fixes until |
|---|---|---|---|---|
| 11 | 8.2 – 8.4 | 12 Mar 2024 | 3 Sep 2025 | **12 Mar 2026 (already ended)** |
| 12 | 8.2 – 8.5 | 24 Feb 2025 | 13 Aug 2026 | **24 Feb 2027** |
| 13 | 8.3 – 8.5 | Q1 2026 | Q3 2027 | Q1 2028 |

`composer audit` on Laravel 11.55.0 reports four `laravel/framework` advisories that Laravel 11 will not get fixes for:

| Advisory | Severity | Fixed in |
|---|---|---|
| CRLF injection in the default `email` validation rule (CVE-2026-48019 + duplicate GHSA) | high | 12.60.0 (mitigated in our code on L11, see §3) |
| Temporary signed URL path confusion | medium | 12.61.1 |
| XSS in the debug page | low (only with `APP_DEBUG=true`) | 12.69.0 |

Laravel 12 gets security fixes only until 24 Feb 2027, so plan the Laravel 13 upgrade for 2027 as well; see §5.

## 3. Breaking changes from the official guide, checked against THIS codebase

Source: [laravel.com/docs/12.x/upgrade](https://laravel.com/docs/12.x/upgrade).

| Change (impact per guide) | Affects us? | Evidence / action |
|---|---|---|
| Dependencies: `laravel/framework ^12.0`, `phpunit ^11.0`, `pest ^3.0` (high) | Yes | Change the framework constraint; PHPUnit is already `^11.0.1`; Pest is not used |
| Carbon 3 (low) | No | Already on Carbon 3.13 |
| Models and UUIDv7 / `HasUuids` (medium) | No | `HasUuids` is not used anywhere (IDs are auto-increment). The activity log's `batch_uuid` is generated by the package |
| Concurrency result index mapping (low) | No | `Concurrency::` is not used |
| Container respects constructor default values (low) | Unlikely | No app class relies on the container filling an optional, nullable class-typed constructor argument; covered by the full test suite |
| Image validation excludes SVG (low) | No (wanted) | Uploads already allow only JPG/PNG/WebP (`ImageUpload`, model MIME rules) |
| Local disk default root `storage/app/private` (low) | No | `config/filesystems.php` already defines `local` → `storage/app/private` explicitly |
| Multi-schema `Schema::getTables()` etc. (low) | No | Not used by app code |
| Nested array `mergeIfMissing` (low) | No | Not used |
| Route precedence for duplicate route names (low) | Check | Route names are unique; verified with the route tests after the upgrade |
| `DatabaseTokenRepository` expires in seconds (very low) | No | Only used through Filament's default password broker configuration (`config/auth.php` `expire` stays in minutes; the framework converts it) |

Project-specific items to revisit:

1. **Email-rule CRLF workaround** (`not_regex:/[\x00-\x1F\x7F]/` in `StoreLeadRequest` and `StoreCommentRequest`). Fixed upstream in 12.60.0. Plan: prove with a test that the plain `email` rule rejects CR/LF on Laravel 12, then remove the workaround. If it doesn't, keep it.
2. **`bootstrap/deprecations.php`** silences a PHP 8.4+ deprecation for `PDO::MYSQL_ATTR_SSL_CA` in the framework's `config/database.php` defaults. Plan: check whether 12.69 still references the constant; remove the file only if it doesn't.
3. The `laravel/laravel` 11.x → 12.x skeleton diff consists of config comments and defaults; no required change for an existing app.

## 4. Effort and risk

- **Effort:** small. One constraint change, `composer update`, then the verification loop: full tests, query budgets, Pint, asset build, CSP check, screenshot matrix, link check, axe.
- **Risk: low.** The guide calls 12.0 a maintenance release, and none of the medium/high items touch our code. The main risk is indirect behaviour changes in Filament, Livewire or Media Library under the new framework minor versions; the suite (361 tests: admin resources × roles, query budgets, SEO, localisation) plus the browser checks cover that.
- **Rollback:** check out `feature/phase-8-plus` and run `composer install` (the lock file there is Laravel 11). No database migration is involved in the upgrade itself.

## 5. After this upgrade

- Laravel 12 security support ends 24 Feb 2027. Laravel 13 (Q1 2026) is supported until Q1 2028, and the installed Filament 3.3 / Livewire / Spatie versions already declare `^13` support. That upgrade is a separate task.
- Filament 3 will eventually stop receiving updates in favour of newer Filament majors; not needed for Laravel 12 or 13 today.

## 6. Result: upgraded, no blocker

- `composer.json`: `laravel/framework` `^11.31` → `^12.0`. Installed **12.69.3**, plus the patch/minor updates listed in §2. No other constraint changed and no application code needed changing for the framework itself.
- **`composer audit`: no advisories** (was 4 `laravel/framework` advisories on 11.55). `npm audit`: 0.
- **Email rule:** Laravel 12 now rejects CR/LF, tabs and other control characters in most positions, but it still **accepts a NUL byte in the local part** (`"vic\0tim@example.test"` passes the plain `email` rule on 12.69.3). The `not_regex:/[\x00-\x1F\x7F]/` guard is therefore **kept** as defence in depth, with an updated comment. `SecurityTest` now covers the advisory vectors, the trailing-newline case (removed by `TrimStrings`, so nothing is stored with a control character) and the NUL case.
- **`bootstrap/deprecations.php` removed:** 12.x's bundled `config/database.php` uses `Pdo\Mysql::ATTR_SSL_CA` instead of the deprecated `PDO::MYSQL_ATTR_SSL_CA`. `php artisan about` with `error_reporting=-1` prints no deprecation notice, and the MySQL connection config still boots.
- Checked items from §3: `config/auth.php` password-reset `expire` stays in minutes (the broker manager multiplies by 60); 92 routes, no duplicate names.
